## 0. 先读这三条，否则一定会走错路

1. **只写 `Engine.locres`，绝对不要碰任何 `pak`。**
   改 `L10NString.dat`（封在 pak 里）会导致**整张表全变问号**，改 1 条和改 3 条都一样，改成纯英文也一样。已在两台干净机器上复现。还原 pak 才恢复正常。
2. **不要用载体字，不要拿日文（ja-JP）的表做数据源或并集。**
   载体字方案是 v1.6.0（日文入口）的历史产物；英文入口走明文简/繁，字体自带完整 CJK cmap。
   混入日文表会污染 key 空间，已被明确禁止。
3. **不要下"游戏内文本改不了"这种结论。**
   已实测：技能、道具、任务、外观、登录、选服全部可汉化，含 11/11 更新内容。

## 1. 一句话原理

UE 的本地化在运行时按 **culture 目录**加载松散 `.locres` 文件：

```
<游戏根>\Engine\Content\Localization\Engine\Platforms\Windows\<culture>\Engine.locres
```

官方客户端不自带任何松散 locres（`pakchunk0` 里 0 个 locres 条目），所以磁盘上这两个文件是**唯一来源**：

- 放进去 → 游戏读我们的中文
- 删掉 → 立即回落官方英文，**不需要备份**

因为 `Engine.locres` 里的 entry 是 `(namespace, key, source_hash) → string_index`，游戏用 key + 源串哈希匹配，所以我们**保留官方 key 与英文源串的 CRC32**，只替换译文。这是它能生效、且不破坏其它逻辑的根本原因。

### 1.1 为什么只有英文入口能用

实测结论（2026-11-12）：

| 实验 | 结果 | 结论 |
|---|---|---|
| en/en-US 放 locres | 全中文，含新内容 | 英文入口读 locres |
| 游戏内切日文 + ja/ja-JP 放同一份 locres | 全日本文，locres 完全不生效 | 日文入口不读 locres |
| 手动把存档 `Engine.ini` 的 `Culture` 改成 `ja-JP` | 依然日文 | 与 Culture 无关 |
| 游戏内切语言 | `Saved_Steam\Config\Windows\Engine.ini` 的 `Culture` 始终是 `en-US` | 语言开关不走 UE culture |

日文入口的文本来自 `Aion2\Content\Paks\L10N\Text\ja-JP\pakchunk503000-Windows_0_P.pak` 里的 `L10NString.dat`，只能走 v1.6.0 的 pak 方案。本方案**不覆盖日文入口**。

### 1.2 登录页底部 4 行英文（已知未解决）

key：`String_UI_GLOBAL_SERVICE_SERVER_DELAY_TIME_NOTIE_body`

- 语料有译文，locres 里有这条，但改成 `NOTIE_TEST_123` 界面毫无变化
- 日文入口（整表被换成中文）能汉化这 4 行
- 结论：这 4 行在英文入口下直读 `L10NString.dat`，绕过 locres
- 状态：**未解决**，且不建议为了 4 行去动 pak

### 1.3 数量单位 K（已定案：保留）

程序固定 `÷1000` 再拼单位字符串。把 `K` 改成 `万` 会让 744,175 显示成 `744.1万`（错 10 倍）。
**决定：保留 K，不改。**

## 3. locres 二进制格式（生成器已实现，勿凭记忆重写）

小端。结构：

```
+0   16B   magic = 0e147475674a03fc4a15909dc3377f1b
+16   u8    version = 1
+17   u64   string_table_offset        ← 先写 0，最后回填
+25   u32   namespace_count
       per namespace:
         FString namespace
         u32 entry_count
           per entry:
             FString key
             u32     source_hash        ← CRC32(UTF-32LE(官方英文源串))
             u32     string_index
@string_table_offset
      u32   string_count
      FString × string_count
```

`FString` 写法（**UTF-16 用负数长度**，这是 UE 的约定）：

```
空串      : i32 0
纯 ASCII  : i32 (字节数+1) + UTF-8 字节 + \0
含非 ASCII: i32 -(字符数+1) + UTF-16LE + \0\0
```

`source_hash` = `zlib.crc32(b''.join(bytes([c,0,0,0]) for c in src.encode('utf-8')))`（即 CRC32 over UTF-32LE）。
**hash 必须用官方英文源串算，不能用中文**——否则游戏匹配不上，该条不生效。

入口是 `aion2_login_locres.build_locres(groups)`，`groups = [(namespace, [(key, source_en, text)]) ]`。
同一个译文只存一次（`strings` 去重），这是 155,208 条 entry 只占 15.7 MB 的原因。

**升级版本号时**要同时改三处：`version.json`、`build.ps1` 的 `$Version`、源码里的 `currentVersion`（cs 与 ps1 各一处）。

### 5.6 更新检查的两个必须项

1. **必须设 TLS 1.2。** `.NET 4.0` 默认只协商 TLS 1.0，GitHub 只接受 TLS 1.2，不设会抛"基础连接已经关闭"，更新检查永远静默失败。
   - C#：`ServicePointManager.SecurityProtocol = (SecurityProtocolType)3072;`
   - PS：`[System.Net.ServicePointManager]::SecurityProtocol = [System.Net.SecurityProtocolType]3072`
2. **必须留镜像。** `raw.githubusercontent.com` 在大陆被阻断，`ghp.ci` 已停用。当前可用镜像：`https://gh-proxy.com/<原始raw地址>`（实测 200）。代码是"主地址失败后 2 秒超时切镜像"，全部失败则静默跳过，不影响汉化功能。

## 6. 游戏更新后的维护流程

1. 启动游戏确认是英文（更新不会影响松散 locres，旧文件仍在生效）
2. 进游戏看新内容：新文本会显示**英文**，这是正常的
3. 提取新的官方 en 表：`python aion2_snapshot.py`，与现有 `en_src.json` 做 key 差分：

```powershell
python aion2_diff.py    # 输出：待翻译 N 条 / 多余 M 条
```
4. 给新增 key 补译文（写进 `plain_zh.dat` / `plain_tw.dat` 对应行）
5. 按 §4.4 重新生成 → 覆盖工具里的 `zh` / `zh-TW` 载荷 → 发版

> 关键点：**更新只影响"新增 key"**。locres 是按 key 匹配的，旧 key 的译文永远有效。
> 这就是本方案比 pak 方案好维护的根本原因：pak 方案每次更新都要重新适配整包。

## 9. 踩过的坑（血泪版）

1. **改 pak → 全问号。** 不是编码问题，是 en-US 的 `L10NString.dat` 任何改动都会让整表失效。别试。
2. **`--revert` 会删掉整个 `Engine\Content\Localization` 目录**（`shutil.rmtree(GAME_LOC)`）。成品工具已改成只删两个文件；写新脚本时别照抄 `--revert`。
3. **`PLAIN_DAT` 在 import 时求值**，同一进程里改 `os.environ` 无效，必须新进程或在 import 前设置。
4. **`.bat` 必须 GBK + CRLF。** 用 LF 会让 cmd 逐行错位，报 `'tlocal'` 之类的残片错误（9009）。
5. **`.ps1` 必须 UTF-8 with BOM**，否则 PowerShell 5.1 按系统码页解析中文，界面乱码。
6. **Steam 版存档在 `%LOCALAPPDATA%\Aion2\Saved_Steam\`**，不是 `Saved_Global`。改 `Engine.ini` 前先确认目录。
7. **`pakread._read_entry_header` 返回 tuple**（`(entry, end)`），不是 dict。
8. **各语言 pak 的 dat 偏移不是固定 53**，要用 `aion2_snapshot.py` 里的 `find_dat()` 扫描头部特征。
9. **语料残留载体字必须为 0**，否则明文表里会混进日文假名。
10. **不要用日文表补条目**，key 空间会乱，已被明确禁止。
11. **源码有仓库副本和本机副本两份**，只改一份会出现"改了但发出去还是旧的"。改完必须两边一致并重新跑 `build.ps1`（分发包里的 `.ps1` 是构建时复制的，不是引用）。
12. **`ghp.ci` 镜像已停用**（DNS 直接解析失败），换 `gh-proxy.com`；`jsdelivr`、`ghfast.top` 在本机也不可达。
13. **不设 TLS 1.2 时更新检查必然失败**，且是静默失败，很容易误以为"代码逻辑没问题"。排查时先打印 `SecurityProtocol`。
14. **Release 资产必须晚于代码、早于 `version.json`**。顺序错了，已安装的用户点更新会拿到 404 或旧包。

## 10. 术语

| 词 | 对应 |
|---|---|
| locres | 本地化资源文件 / 本地化字符串表（Localization Resource），**不是**"本地资源" |
| culture | 语言目录名：`en`、`en-US`、`ja`、`ja-JP` … |
| namespace | locres 内的命名空间，本项目主用小写无、`AION2` |
| source_hash | 官方英文源串的 CRC32(UTF-32LE)，locres 匹配 key 用的 |
| 载体字 | v1.6.0 用日文字形拼汉字的方案，英文入口**不使用** |
